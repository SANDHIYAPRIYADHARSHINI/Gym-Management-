# Viva checklist

1. Start Neo4j, create constraints, seed an empty application database and log in as admin.
2. Show the baseline: 5 members, 46000 rupees collected, Meena alone owing 3000.
3. Open Graph Explorer; explain six colours and seven relationships, zoom/pan and accessible list.
4. Enable Query demo. Register a synthetic member with valid branch/plan IDs. Inspect committed Cypher and masked phone parameters.
5. Find the new member and first payment in the entity lists and graph.
6. Register with an unknown branch or plan; show the error and verify no member was saved.
7. Record a positive payment, then try zero and show rejection.
8. Change a plan and inspect history.
9. Try deleting a member with payments and explain the guard.
10. Run all nine Evaluation Studio queries, including the date filter.
11. Sign in as Meena and Karan to demonstrate API-restricted portals.
12. Explain the MODEL.md mapping, Community integrity responsibilities and the absence of performance claims.
13. Run the tests and disclose all limitations in VERIFICATION.md.

Screenshots must come from the running app after successful database reads. No screenshot is supplied as evidence for functionality that was not verified.
